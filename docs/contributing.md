# Contributing

感谢你愿意补充这份手册。这个仓库最需要的是真实、具体、可验证的经验，而不是泛泛而谈的“应该多宣传”。

## 内容标准

请尽量做到：

- 写清楚游戏类型、平台、阶段和目标。
- 区分事实、观察和个人判断。
- 给出来源链接，优先使用官方文档、平台公告、开发者复盘和可公开验证的数据。
- 说明时间。中国平台规则和流量环境变化很快，旧经验要标注年份。
- 保护隐私。不要公开合同、报价、后台数据或聊天记录，除非你有权公开。

## 推荐格式

经验类内容建议包含：

- 背景：游戏类型、团队规模、目标地区、发售阶段。
- 做法：具体渠道、素材、节奏、预算、人力。
- 结果：愿望单、播放、点击、转化、评论质量、销量或可公开的替代指标。
- 复盘：哪些有效，哪些无效，下次怎么改。

## 不建议提交

- 无来源的市场规模数字。
- 复制平台文章全文。
- 单纯推广自己的服务、发行商或工具。
- “万能公式”和保证结果的承诺。

## 提交方式

1. Fork 仓库。
2. 新建分支，例如 `case/steam-demo-2026`。
3. 修改或新增文档。
4. 提交 Pull Request，并说明来源、适用范围和更新时间。

如果你不确定放在哪里，可以先开 Issue。
